Homework 3: Toy ECC, Caesar Cipher & Cryptanalysis

An in-depth analysis of Asymmetric vs. Symmetric Schemes, Statistical Frequency Attacks, and Restricted Key Space Exploitation

1. Toy ECC Scheme (secp256k1 over Z_17)

Setup: Curve equation y² = x³ + 7 (mod 17) with base generator G = (1, 5).
The recipient chooses a private scalar k = 6. The computed public key is Q = 6G = (8, 3).

Encryption Procedure (ElGamal-EC style):
1. Map each character to a discrete curve point PM.
2. Choose an ephemeral secret scalar r = 3.
3. Compute two ciphertext points: C₁ = r · G = 3(1,5) = (10, 6) and C₂ = PM + (r · Q) = PM + (13, 7).

Decryption Procedure:
1. Reconstruct the shared secret using the private key: S = k · C₁ = 6(10, 6) = (13, 7).
2. Subtract S from C₂ to recover the message point: PM = C₂ - S = C₂ + (-S).

2. The Caesar Cipher

The Caesar cipher is a monoalphabetic symmetric substitution cipher. Each character in the message is shifted by a fixed key integer $k \in [0..25]$:
E(x) = (x + k) mod 26,   D(x) = (x - k) mod 26

Comparison: Toy ECC vs. Caesar Cipher

Property Caesar Cipher Toy ECC Scheme
Cipher Architecture Symmetric (Same key $k$ for encryption and decryption). Asymmetric / Hybrid (Public key $Q$ encrypts, Private key $k$ decrypts).
Key Space Size Tiny ($26$ possible keys). Restricted in Toy demo ($18$ possible points); $2^{256}$ in real secp256k1.
Mathematical Foundation Modular arithmetic on alphabet positions (1D shift). Geometric group operations over discrete elliptic curve fields (2D points).
Statistical Properties Preserves exact unigram and n-gram frequency distributions of plaintext. Masks coordinates using ephemeral scalar $r$, scattering points across $\mathbb{Z}_p$.

3. Statistical Cryptanalysis of the Caesar Cipher

Because monoalphabetic substitution shifts every letter identically, it fails to alter the underlying letter frequencies of natural language. We exploit this by calculating the Chi-Squared ($\chi^2$) goodness-of-fit statistic for all 26 candidate shifts against standard English letter frequencies:

$$\chi^2 = \sum_{L \in \text{A--Z}} \frac{(O_L - E_L)^2}{E_L}$$

The shift candidate producing the lowest $\chi^2$ value corresponds to the true encryption key.

Effectiveness, Limitations, and Alternative Approaches

  • Effectiveness & Limitations: Frequency analysis breaks medium-to-long ciphertexts instantly. However, on very short texts (under 25–30 characters) or messages with abnormal letter distributions (e.g., lipograms), unigram frequencies fluctuate, leading to incorrect key selection.
  • Exhaustive Key Search (Brute-Force): Tests all 26 possible keys ($O(26)$). For small key spaces, this is trivial for a human to scan visually, but requires dictionary lookups for automated detection.
  • N-Gram Scoring (Bigrams / Trigrams): Evaluates probabilities of adjacent letter pairs (e.g., "TH", "HE", "IN") using log-likelihoods. This approach is significantly more robust than single-letter analysis on short texts because it captures local grammatical syntax.

4. Key Recovery Attack on Restricted-Space ECC

In this toy setup, the private key $k$ is artificially restricted to a tiny range ($k \in [1..16]$). An attacker who knows the generator $G = (1, 5)$ and the public key $Q = (8, 3)$ can solve the Elliptic Curve Discrete Logarithm Problem (ECDLP) by brute-forcing scalar multiplications until $k \cdot G = Q$.

Comparison: Statistical Attack vs. Key Space Brute-Force

  • Caesar Attack Basis: Exploits linguistic redundancy and statistical structural flaws in the encryption transformation (the language is not uniformly random).
  • Toy ECC Attack Basis: Exploits insufficient key entropy. The math of the curve itself remains unbroken, but the secret range is small enough to allow linear search.
  • Feasibility on Real ECC: On a standard secp256k1 implementation, the key space is $n \approx 2^{256}$. The best general-purpose attacks (Pollard's rho) require $O(\sqrt{n}) \approx 2^{128}$ operations. Running this brute-force attack on a properly configured 256-bit curve would take billions of years with all the world's supercomputers combined.

Design Weaknesses in the Toy Scheme

The vulnerability in this demonstration arises primarily from the artificial key space restriction ($p=17$). However, secondary design weaknesses exist in the toy implementation:

  • Deterministic Mapping without Padding: Directly mapping characters to static points without randomized padding (like PKCS#1 or OAEP in RSA/ECC) causes identical plaintext characters to yield identical ciphertext points when the same ephemeral key $r$ is reused.
  • Lack of Ephemeral Randomness: If the ephemeral scalar $r$ is predictable or reused across different messages, an attacker can extract the private key or decrypt all communications instantly.
